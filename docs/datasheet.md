# Datasheet — LusoSupport-PT

This datasheet follows the *Datasheets for Datasets* framework (Gebru et al., 2021)
to document the motivation, composition, collection process, and recommended uses of
**LusoSupport-PT**. It is intended for prospective users, buyers, reviewers, and
researchers who need to assess the dataset's fitness for a given purpose.

- **Dataset:** LusoSupport-PT
- **Version:** v1 (5,149 rows)
- **Language:** Portuguese — European variant (`pt-PT`)
- **Licence:** CC BY 4.0 (Lite/200-row sample) · commercial/personal licences for the full dataset (see [`LICENCE-COMMERCIAL.md`](../LICENCE-COMMERCIAL.md))
- **Maintainer:** @ariazevedopt (GitHub) / @ariazevedo (Hugging Face)

---

## 1. Motivation

**For what purpose was the dataset created?**
To provide a purpose-built, structured **European Portuguese (pt-PT)** customer-support
instruction dataset for LLM fine-tuning, prompting, evaluation, and support-automation
workflows. Publicly available Portuguese datasets are typically generic corpora,
academic benchmarks, or Brazilian-Portuguese-oriented (`pt-BR`); none combine
support-domain focus, instruction formatting, and enforced pt-PT vocabulary.

**Who created it and who funded it?**
Created and maintained by @ariazevedopt as an independent, self-funded project.

---

## 2. Composition

**What do the instances represent?**
Each instance is a single synthetic customer-support interaction expressed as an
instruction-tuning row: an `instruction`, an `input` (a customer message plus optional
context), and an `output` (the target agent response or a structured classification).

**How many instances are there?**
- **5,149** rows in the full processed dataset (`datasets/processed/lusosupport_pt_v1.jsonl`).
- **200** rows in the free HF Lite sample (`datasets/hf-lite/lusosupport_pt_lite.jsonl`).
- **64** hand-crafted seed rows (`datasets/raw/seed_examples.jsonl`) are always merged into the full dataset as a quality floor.

**What structure does each instance have?**
See [`docs/schema.md`](schema.md) for the canonical schema. Key axes:

| Axis | Count | Values |
|---|---|---|
| Domains | 8 | `ecommerce`, `subscriptions`, `saas`, `telecom`, `utilities`, `travel`, `marketplace`, `billing_accounts` |
| Task types | 8 | `response_generation`, `email_reply`, `summarization`, `intent_classification`, `urgency_classification`, `rewrite_professional`, `next_action_suggestion`, `faq_answer` |
| Customer intents | 18 | e.g. `refund_request`, `password_reset`, `invoice_request`, `booking_change`, `duplicate_charge`, … |

**Is any information missing?**
No. Every row passes the `validate.py` rule set, and 0 rows carry placeholder metadata
(a bug fixed in v1.0.0). Every row has a real `subdomain`.

**Are there duplicates?**
Exact duplicates (on `instruction + input + output`) are removed via SHA-256
fingerprinting (`dedupe.py`). Near-duplicate reuse of canned outputs is bounded by a
diversity gate: every task type has a unique-output ratio of **42–77%** (≥40% enforced).

**Is the dataset self-contained?**
Yes. It contains no links to external resources and no dependency on third-party data.

**Does it contain confidential or personal data?**
No. All content is synthetic. Rows contain no real personal data; the `metadata.contains_pii`
flag is present for completeness but the dataset avoids real identifiers by design.

**Does it contain sensitive or offensive content?**
No. The dataset excludes medical, legal, tax, investment, and other regulated advice, as
well as abusive or harmful content (see the "Out of scope" section of the README).

---

## 3. Collection process

**How was the data collected/generated?**
The data is **fully synthetic**, generated by a deterministic, template-driven Python
pipeline (`scripts/`). Human-written pt-PT templates (`responses.py`,
`responses_expansion.py`, `scenarios.py`) are combined with tone/domain substitutions and
derived metadata, then validated and deduplicated. No teacher-LLM generation is used, so
there are no upstream model-licensing constraints on the outputs.

**Who was involved?**
Authored and reviewed by the maintainer, with an interactive review loop
(`make review` / `make review-browser`) used to curate flagged rows.

**Over what timeframe?**
Developed iteratively from April 2026; the v1 quality-overhaul release is dated 2026-08-07.

---

## 4. Preprocessing / cleaning / labelling

Rows are generated with structured labels (domain, task type, intent, tone, channel,
difficulty, escalation, PII flag) rather than post-hoc annotation. Cleaning steps:
validation against 20+ rules (`validate.py`), exact-duplicate removal (`dedupe.py`), and
an output-diversity gate (`quality_report.py`). The raw seed set and the generation
scripts are all included in the repository for full reproducibility.

---

## 5. Uses

**What is the dataset intended for?**
- Fine-tuning / instruction-tuning of Portuguese (pt-PT) support assistants.
- Few-shot prompting and prompt-engineering experiments.
- Training/evaluating intent- and urgency-classification models.
- Building helpdesk copilots, RAG pipelines, and support-automation prototypes.

See [`docs/use-cases.md`](use-cases.md) and [`docs/integration.md`](integration.md) for recipes.

**What should it not be used for?**
- As a source of factual company policies (outputs are illustrative, not authoritative).
- For regulated advice (medical, legal, tax, investment).
- As a Brazilian-Portuguese (`pt-BR`) resource — vocabulary and register are pt-PT.
- Redistribution/resale of the raw files (prohibited by the commercial licence).

**Are there risks or limitations?**
- The data is synthetic and template-derived; it reflects realistic but not real support
  transcripts, and may under-represent rare or highly idiosyncratic phrasing.
- Coverage is bounded by the 8 domains × 8 task types × 18 intents defined for v1.
